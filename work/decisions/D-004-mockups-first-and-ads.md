# D-004: Mock up UI options before building, and find publishers through ads

- **Date:** 2026-11-15
- **Status:** accepted
- **Answers:** Q-002
- **Projects:** [ui-mockups](../projects/ui-mockups.md), [pilot-publishers](../projects/pilot-publishers.md), [notify-core](../projects/notify-core.md)

## Context

The first plan had the owner hand-recruiting 3–5 publishers and a session
picking a stack straight away. The owner wants two changes. First, see UI
options before committing to anything. Second, don't rely on finding
publishers personally; run ads instead.

## Decision

1. Before any stack choice or build, sessions produce several UI mockup
   options for the key screens. The owner picks a direction, and that
   choice is written up as a decision.
2. First publishers come from ads, run by the owner, pointing at a landing
   page with a waitlist sign-up. The landing page and the mockups double as
   the ad creative.

## Options considered

- **Mockups first, ads to a waitlist**: cheap to change direction, and the
  waitlist measures real demand before anything is built.
- **Hand-recruit publishers, build straight away**: closer feedback, but
  commits to a design early and depends on the owner's network.

## Consequences

Sessions still never spend money or start ads (D-001); the owner runs the
ad account and sets the budget. A landing page has to be published before
ads can run, which only the owner can do. Waitlist sign-ups collect email
addresses, so the page needs a short privacy note. Revisit if ads bring
sign-ups that don't turn into active publishers. Hand-recruiting a few
alongside them stays an option.
